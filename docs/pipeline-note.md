# 構成の変更（2026-09-07）

`docs/pipeline.md` は 3DGS を前提に書かれている。**3DGS は採用しない方針に
変わった**ので、現在の構成はこちらを参照する。`pipeline.md` は経緯の記録として残す。

## 現在の構成 — iPad 完結

```
撮影 104 秒
  ├─ MDR バンドル（RGB / 深度 / 信頼度 / ポーズ）
  ├─ ARMeshAnchor（撮影中に構築、追加コストなし）
  └─ RoomPlan（同一 ARSession、座標系一致）
         ↓ 停止
  テクスチャ付きメッシュ 15 秒（端末上、Metal）
  room.json（壁・ドア・窓・家具）
         ↓
  間取り図 / 家具配置（Mac 側または端末上）
```

**Mac サーバは要らない。**「アップロードして 5 分待つ」という要件が消えた。

## なぜ 3DGS を外したか

サーバ側で品質を上げる 3 つの施策を実測し、**計算資源を増やす 2 つが空振り**した。

| 施策 | 数値 | 盲検の目視 |
|---|---|---|
| 解像度 480 → 1920 | ±0.18 dB | 区別できず |
| ガウシアン 50万 → 100万 | +0.44 dB | 区別できず |
| 露出補正 | +1.64 dB | 有意に良い |

律速は撮影時のブレだった。**入力画像に 480 を超える情報がない**（露光 1/100 秒 ×
角速度 25.4°/s で 1 枚あたり約 10 画素のブレ、実効解像度 200 画素相当）。

詳細は [`experiments-server-quality.md`](experiments-server-quality.md)。

## RoomPlan の同居

iOS 17 の `RoomCaptureSession(arSession:)` で MDR 撮影と同じセッションに載る。
**採用フレームは減らない**（160 → 166 枚）。座標系が一致するので、間取り図を
3D モデルに重ねる位置合わせが不要になる（床の高さの差 3.4cm で確認）。

**RoomPlan は共有セッションから `sceneDepth` を落とす。** 起動 2 秒後に
再適用して回避している（`capture/Sources/RoomScan.swift`）。

## 次に効くのは撮影側

サーバ側は頭打ち。品質を上げるなら撮影を直す。

| 施策 | 期待 | コスト |
|---|---|---|
| ブレたフレームを捨てる | sharpness は 25〜3547 と 140 倍ばらつく | ほぼゼロ |
| パンを半分の速度に（25°/s → 12°/s） | ブレ 10px → 5px | 撮影時間が倍 |
| 撮影者への速度警告 | 10 画素のブレは画面では知覚できない | UI の実装 |

角速度の上限は計算できる: `ブレ[px] = 角速度[rad/s] × 16.2`。
5px に抑えるには 17.7°/s 以下で、**現状の撮影は 70% がこれを超えている**。
