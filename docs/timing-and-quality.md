# 所要時間と品質の実測

最終更新 2026-08-24 / 計測環境 iPad Pro 11" 2020 (A12Z, LiDAR) + MacBook Pro M1 Max

本番の部屋を実際に撮影して計測した値のみを載せる。推定値には「未計測」と明記する。

## 1. 要約

**3D モデルは 2 種類あり、用途が違う。**

| | **iPad 単体** | **Mac で高精細化** |
|---|---|---|
| 撮影から完成まで | **約 3.5 分** | **約 6.5 分**（+ 転送時間） |
| 形式 | テクスチャ付きメッシュ (GLB / USDZ) | 3D Gaussian Splatting (PLY) |
| 見た目 | 部屋と認識できる。輪郭が甘い | 写真に近い |
| 閲覧 | iPad の Quick Look でその場で | 専用ビューア (madoriba tour) |
| 用途 | 現地での即時確認、寸法・間取り | 営業資料としての内見体験 |

現地で撮った直後に iPad で確認でき、写実的なモデルは Mac に持ち帰って作る、という二段構えになっている。

## 2. 時間の内訳

### 撮影（iPad）

| 実測 | フレーム数 | バンドル容量 |
|---|---|---|
| 109 秒 | 469 | 310 MB |
| 126 秒 | 451 | — |

**約 2 分。** 部屋の外周を 3 パス回る手順による。A12Z の発熱対策で 3 分の自動停止を入れてあるが、
本番スキャンはいずれもその半分以下で終わっている。

### iPad 単体でのモデル生成

| 段階 | 実測 |
|---|---|
| LiDAR メッシュ統合 | 撮影と同時（追加時間なし） |
| UV 展開 + テクスチャ焼き込み + GLB/USDZ 書き出し | **79 秒** |

ARKit が撮影中に構築したメッシュをそのまま使うため、撮影後の追加処理は
テクスチャの焼き込みだけで済む。処理は全て Metal のコンピュートシェーダで行う。

**撮影 126 秒 + 生成 79 秒 = 205 秒（約 3.5 分）**

### Mac での高精細化

| 段階 | 実測 |
|---|---|
| 転送（iPad → Mac、310 MB） | **未計測**（現状は Files アプリ経由の手動コピー） |
| ポーズ精密化 (ICP) | 11.9 秒 |
| COLMAP 形式への変換 | 0.03 秒 |
| LiDAR 初期点群の生成（479,206 点） | 8.3 秒 |
| 視点 (station) 抽出 | 0.02 秒 |
| **3DGS 学習 10,000 iteration** | **262 秒** |
| 小計 | **282 秒** |

**撮影 109 秒 + 処理 282 秒 = 391 秒（約 6.5 分）+ 転送時間**

サーバ処理の要件は 5 分（300 秒）で、282 秒はこれを満たす。ただし**余裕は 18 秒しかない。**
実際、他の処理が同時に GPU を使っただけで 302 秒に伸びた計測がある。

## 3. 各モデルの中身

| | iPad 単体（メッシュ） | Mac 高精細（3DGS） |
|---|---|---|
| 構成要素 | 179,015 面 / 425,399 頂点 | 500,000 ガウシアン |
| テクスチャ | 2048×2048 JPEG アトラス 1 枚 | なし（各ガウシアンが色を持つ） |
| ファイル | GLB 13 MB / USDZ 33 MB | PLY 113 MB |
| 再現精度 (PSNR) | 約 16 dB | **約 22.5 dB** |

**PSNR の差 6.5 dB は、目視でもはっきり分かる差。**
メッシュ側は形状の誤差（数 mm〜1 cm）にテクスチャを貼り付けるため、
家具の輪郭や細い部材でテクスチャが引き伸ばされる。
3DGS のガウシアンはメッシュに縛られないので、この制約を受けない。

## 4. なぜこの設定なのか

### 学習解像度は 640 に固定

| 学習解像度 | 3DGS 学習 | PSNR | 5 分要件 |
|---|---|---|---|
| **640（採用）** | **262 秒** | 22.53 | ○ |
| 960 | 333 秒 | 22.75 | × 53 秒超過 |
| 1920 | 712 秒 | 22.95 | × 大幅超過 |

960 は +0.21 dB のために 71 秒、1920 はさらに +0.20 dB のために 379 秒かかる。
5 分要件の下では 640 以外を選ぶ理由がないため、**引数で変更できないようにしてある。**

高解像度への対応は、要件を緩めるか処理環境を変えるかの判断とセットになるので、
後付けの課題として切り離している。

### テクスチャは解像度を上げても改善しない

アトラスを 2048² → 4096² にしても PSNR は 16.04 → 16.03 で変わらなかった。
ポーズ誤差を 64% 削っても、形状誤差を 20% 改善しても、3 回とも効果ゼロだった。

**テクスチャの品質は貼る先の形状精度で頭打ちになる。**
iPad 単体モデルをこれ以上良くするには、解像度ではなく形状を直す必要がある。

## 5. 現状の制約

PM 判断が必要な項目。

| 項目 | 状態 |
|---|---|
| **転送** | 手動。Files アプリで iPad から Mac へコピーしている。自動化は未実装 |
| **サーバ** | 開発機の MacBook Pro をそのまま使っている。同時に 1 件しか処理できない |
| **対応範囲** | 単一の部屋のみ。複数部屋の統合は未実装 |
| **中断・復帰** | 撮影中の着信、メモリ逼迫、バックグラウンド遷移での挙動が未確認 |
| **撮影ガイダンス** | 未取得領域の可視化は ARKit のワイヤーフレーム表示で代用中 |
| **iOS 側のテスト** | なし。実機で動かして目視するしか検証手段がない |

Mac 側の変換処理には 18 件の自動テストがある。

## 6. 計測の再現手順

```bash
# iPad 単体モデル: アプリ内の「3D モデルを作成」から。所要時間がアプリに表示される

# Mac 高精細モデル
mdr2colmap server room-xxxx.mdr -o scene/ \
  --brush vendor/brush/target/release/brush
```

段階ごとの所要秒数が表で出力される。

**GPU を使う計測は必ず排他で行うこと。** ビューアや他の学習と同時に走らせると
3DGS が 262 秒 → 302 秒に伸びる。過去に 34 分の処理を 103 分と誤計測した例がある。
