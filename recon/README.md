# recon — MDR バンドルから間取り図と家具配置を作る

iPad で撮った `.mdr` バンドルを Mac 側で扱うツール群。

```bash
mdr2colmap verify    room-xxxx.mdr                        # 座標変換とポーズの検証
mdr2colmap roomplan  room-xxxx.mdr -o plan/               # RoomPlan から間取り図
mdr2colmap arrange   room-xxxx.mdr --moves m.json -o out/ # 家具を切り分けて動かす
mdr2colmap floorplan room-xxxx.mdr -o plan/               # メッシュから間取り（旧データ用）
```

## 3DGS は採用しない

**サーバ側で計算資源を増やしても品質が上がらない**と実測で確認したため。

| 施策 | 数値 | 盲検の目視 |
|---|---|---|
| 解像度 480 → 1920 | ±0.18 dB（反復分散と同程度） | 区別できず |
| ガウシアン 50万 → 100万 | +0.44 dB | 区別できず |
| 露出補正 | +1.64 dB | 有意に良い（3DGS 上で） |

解像度が効かない理由も特定済み。**入力画像に 480 を超える情報がない。**
480 に落として戻しても原寸に対し 39.2 dB。露光 1/100 秒のあいだにカメラが
約 10 画素動いており、実効解像度は 200 画素相当しかない。

経緯は [`docs/experiments-server-quality.md`](../docs/experiments-server-quality.md)。

削除したもの: COLMAP 書き出し、初期点群の構築、ポーズ精密化、station 抽出、
TSDF 再融合、パノラマ合成、splat ビューア（`tour/`）。座標変換だけ `coords.py` に残した。

## 現在の構成

**すべて iPad 上で完結する。** Mac サーバは要らない。

```
撮影 104 秒（RoomPlan 同時実行、座標系一致）
  → テクスチャ付きメッシュ 15 秒（端末上）
  → room.json（壁・ドア・窓・家具）
```

Mac 側は間取り図の生成、家具の切り分け、検証を担う。

## モジュール

| | 役割 |
|---|---|
| `mdr.py` | バンドルの読み込み。ポーズ・深度・信頼度・EXIF |
| `coords.py` | ARKit ↔ OpenCV の座標変換。**変換規約はここに集約する** |
| `mesh.py` | メッシュの PLY 読み込み |
| `roomplan.py` | `room.json` → 間取り図（SVG / DXF）。壁・ドア・窓・家具 |
| `segment.py` | RoomPlan の箱で家具を切り分け、動かす |
| `floorplan.py` | メッシュから壁を推定（Manhattan 前提、開口部は検出できない） |
| `texture.py` | テクスチャ焼き込み。iOS 実装（Metal）の参照実装 |
| `verify.py` | 再投影による座標変換の検証 |
| `pointcloud.py` | 深度の非投影。`verify` と `photometric` が使う |
| `photometric.py` | フレーム間の露出差を揃える。**テクスチャ経路での効果は未確定** |

## 間取り図の 2 経路

| | RoomPlan | メッシュ |
|---|---|---|
| 必要なもの | `room.json`（撮影時に同時取得） | `mesh.ply` のみ |
| 内法 | 3.14 × 3.60 m | 3.05 × 3.60 m |
| 面積 | 11.29 m² | 11.0 m² |
| 壁 | 4 枚 | 4 枚 |
| **ドア** | **3 枚（幅つき）** | **0 枚** |
| 家具 | 4 個 | なし |

寸法は 3cm 以内で一致する。**開口部が取れるかが決定的な差**で、
メッシュ経路の検出は「壁面の鉛直被覆の欠落」を探す発見的な手法のため、
ドアが閉まっていると壁と区別できない。

`room.json` を持たない旧データには `floorplan` を使う。寸法図としては成立するが、
ドアと窓のない平面図は不動産の資料にならない。

## 家具の切り分け

```bash
mdr2colmap arrange room-xxxx.mdr --moves moves.json -o out/
```

RoomPlan は家具を向き付き境界箱で返すので、箱の中の面を選べば分離できる。
実測（`room-33d49373` / 148,897 面）:

```
収納 13,852 / テーブル 6,445 / 椅子 1,245 / ベッド 5,405
部屋 121,950   床付近で除外 13,742
合計 148,897 = 元と一致
```

切り出した部品の実寸は宣言寸法と 2〜10% 以内で一致する。

**床から 4cm 以内の面は家具に含めない。** RoomPlan の箱は床面から始まるので、
そのまま切ると椅子を動かしたときに床が付いてくる。

既知の限界: 動かした跡に穴が空く（家具の裏は撮影されていない）。

## テスト

```bash
.venv/bin/python -m pytest tests -q
```

37 件。列優先/行優先の取り違え、上方向の軸、回転の中心、床の巻き込みは
いずれも「それらしく動いてしまう」ため、既知の答えを持つ合成データで押さえている。
